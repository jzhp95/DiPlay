# 车机连接与方控调试

原来的 `build-apks.sh` / `build-apks.ps1` 会构建包含此功能的普通版和 UID 版，不需要另加构建参数。APK 文件名带本轮构建时间；请把实际测试的文件名与报告一起提供，便于定位代码版本。Flyme EAS 方控请优先复测已经在该车走通的 UID 版。

## 上车测试步骤

1. 打开应用首页 → 设置 → 诊断，开启 **详细调试日志**。默认关闭，开启后立即生效，退出应用和重启后保留开关状态。
2. 重新连接 iPhone，等待 CarPlay 画面出现。要分析连接失败，请在连接之前开启记录。
3. 依次测试上一曲、下一曲、播放/暂停，每次间隔约两秒。测试期间记下哪些按键有效、车机原音乐是否响应，以及手机是否来电或切换过音源。
4. 出现问题后可回首页 → 设置 → 诊断，点 **添加问题标记**，记录当下时间。返回首页不会自动断开连接。
5. 如需测试释放焦点，先保持记录开启，在首页主动断开 CarPlay，再测试车机原音乐。确认现象后才关闭记录。
6. 关闭 **详细调试日志**，点击 **保存诊断报告**；也可选择保存位置，或使用已有的 **在手机上获取报告** 入口。关闭开关不会删除已录日志。
7. 提供导出的完整报告，并附 APK 文件名、操作顺序、异常发生的大概时间。无需另行执行 adb/logcat。

## 报告能看到什么

详细日志位于报告的 `Detailed connection / focus / wheel event recording` 段，包含日期、毫秒时间、运行时钟、进程号和进程内递增序号。已有报告中的环境、崩溃、进程退出、方控和 Flyme 状态仍会保留。

| 类别 | 记录内容 |
| --- | --- |
| 应用与安装身份 | 包名、UID、版本、安装更新时间、平台签名匹配、OEM 权限与系统型号 |
| 连接 | 首页连接操作、前置条件等待、USB/无线连接阶段、认证与握手的安全状态信息、重试、错误、会话激活和结束；控制器代次用于区分旧回调 |
| 音频焦点 | Android 焦点申请结果、gain/loss 回调、恢复申请、释放请求与 abandon 返回值 |
| Flyme EAS | 能力检查、Binder 连接与注册、源类型 36、requestPlay、焦点查询和变化、原始方控码及接受/拦截结果、注销与超时 |
| 按键路径 | 无障碍服务与 MediaSession 收到的按键码、动作、重复次数、扫描码、设备编号、保留或放行、EAS 去重结果、向 CarPlay 或车机视频播放器的路由 |
| 发往 iPhone | 媒体命令入队/拒绝、任务开始执行、HID 按下及松开是否完成事件通道写入 |
| iPhone 状态 | 播放/暂停变化、位置、时长及元数据变化标志；可与发出的按键时间对照 |
| 用户标记 | `USER_MARK` 表示点击“添加问题标记”的时刻 |

`queued=true` 或旧方控摘要里的 `sent=true` 只表示任务已入队。`downWritten=true upWritten=true` 表示按下和松开已写入事件通道，仍不是 iPhone 已切歌的确认；需要结合之后的播放状态变化和实测现象判断。

## 记录范围

- 记录本应用能观察到的事件。若按键被车机系统或其他应用提前拦截，本应用无法记录那个未收到的事件；此时应结合焦点与 EAS 状态排查。
- 记录器独立于 CarPlay 页面的生命周期，在打开菜单、回首页、后台运行及连接重试期间继续工作。关闭开关只停止详细记录，原有基础诊断仍保留。
- 日志后台写入，本地保留当前文件及七份轮转文件，每份约 512 KiB，总计约 4 MiB；超限覆盖最早记录。队列最多保留 1024 条待写事件，过载时丢弃最早待写项；报告中的 `queueDropped` 标明本进程丢弃数量。
- 导出前最多等待两秒清空待写队列，`writerFlushed=false` 表示仍可能存在尚未写入的事件。异常断电或进程被杀时，最后一小段待写日志可能来不及保存；此前已落盘的内容在下次启动后仍可导出。
- 写盘前沿用现有脱敏规则，不采集原始音视频、协议数据包、认证密钥和密码；IP/MAC 等地址会被替换，输入文字的按键不记录。日志不会自动上传。
