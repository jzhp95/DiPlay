# 统一车机弹窗

目标：解决应用弹窗字体小、按钮难点；保留每个设置的保存、校验、取消及重连语义。

参考用户指定的两个 APK 已解码资源。master 包（SHA-256 fcd4bb55dfbb1ee928ec34803a747f9f35f630ff495cf1b92242474a15e58a72）定义 Flyme Auto 弹窗主题、圆角背景、独立按钮栏、标题和正文排版，包含宽按钮及遮罩；sign 1.3.2 包（SHA-256 fdf8ab7aee2bcb236b80a0e0cca28bf367236352c49dafa1754659a5224b0298）主要使用 Android Material 窗口主题。上述为静态资源观察，没有在车机运行这两个 APK 来验证所有弹窗的实际外观。

方案比较：仅改主题难以覆盖代码写死的字体和按钮尺寸；完全替换 Dialog 会触及现有 getButton、延迟校验及列表回调；采用统一 Builder 和独立外观适配层，保留原生 AlertDialog 的交互生命周期，集中控制面板、排版和触控尺寸。选择第三种。

规格：标题 26sp，正文与按钮至少 20sp，输入至少 22sp；按钮最小 72dp，选项行最小 68dp。面板最大宽度 760dp，依当前窗口限制宽度；24dp 圆角、背景遮罩、独立实心操作按钮、按下涟漪和键盘焦点边框。深浅色使用现有 DiPlayPalette。按钮空间不足时纵排，横排等宽且等高；正文、列表及长表单支持滚动。使用 sp/dp，不复制厂商像素尺寸。

改动集中在 AppDialogs 与 CarDialogStyle，接入首页、设置、CarPlay 设置退出确认、方控测试确认及时间选择弹窗。保留 setOnShowListener、getButton、列表选择、输入校验不关闭、关闭监听与取消行为。安全区编辑器的预览和特殊窗口尺寸保留。系统 USB 授权和 Android 权限窗口不改；搜索下拉与 Toast 不属于本次模态弹窗范围。

验证：原生控件交互回归（确认、取消、列表、校验、自定义 OnShow）；紧凑和宽屏、大字体、深浅色及 RTL 截图；执行仓库 CI 命令，并如实记录环境限制。

## 实现与检查记录

统一封装保留 Android AlertDialog 作为交互后端，采用自己控制尺寸的面板和按钮栏；通过附着监听应用样式，不占用调用方的 OnShowListener。沿用实际 Button 对象，不复制确认回调。长列表保留原适配器的事件和选中状态，按需装饰新生成的选项行。自定义安全区编辑器仍保留独立 Dialog 和预览尺寸。

已做独立资源/原生控件验证：6 个交互用例分别覆盖 API 25、29、33；4 个原生绘制截图覆盖宽屏、640×360 短屏、高密度及 RTL，字体缩放 1.5 倍。截图输出到 `build/reports/car-dialogs/`。测试编译真实 AppDialogs、CarDialogStyle、DiPlayPalette 和仓库测试代码；仅用测试目录中的简化外观解析函数隔离无关依赖，因此不代替完整 APP 集成测试。

项目 CI 命令已尝试，Gradle wrapper 因用户缓存 `.zip.lck` 写入被限制（Operation not permitted）退出，未完成整包构建。车机 OEM 窗口实现、键盘弹出行为及实际触控仍需重新打包后实机验证。系统权限窗口、Toast、搜索下拉未替换。
