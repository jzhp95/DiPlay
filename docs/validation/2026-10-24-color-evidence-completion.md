# 画面颜色测试补全版

版本 0.2.22-hud-test / versionCode 41，Android 9 / API28 起。安装包签名与上一测试包一致，可覆盖安装；根目录旧的“DiPlay-画面颜色测试.apk”入口也已更新，旧包保留在原交付 artifacts 目录。

## 使用

1. 首页 → 测试工具 → 画面颜色 → 开始／继续测试。
2. 先完成默认解码及严格软件解码标准片的观察。各项可记录正常、发白、浅灰变白、黑色发灰、偏色、无法显示或跳过。
3. 正式主屏项目会重连 iPhone，进入实际 CarPlayHostActivity。画面出现后点“全屏观察 8 秒”，控件自动恢复后记录；可以单独标记“隐藏测试控件时颜色不同”。每项结束会关闭本次测试连接，再进入下一项。普通投屏、画面、帧率及解码设置不写入测试值。
4. 完成后看采集完整性，再保存并分享 ZIP。“不支持”或“平台未报告”会保留具体限制，不计为齐全；重复同一项不一定能补齐平台接口缺失。截图失败、连接中断等其他缺项可在同一页选择对应项目补采。

## 覆盖与证据

- 26 项：8 个默认解码标准片、8 个严格软件标准片（H.264/HEVC × 全/有限范围 × 纹理/直接输出），10 个真实主屏配置（当前、纹理、直接、平滑、两种路径的全/有限范围请求、两种软件路径）。严格软件不可用时禁止默认硬件回退。
- 源 CSD 原始字节（Base64）、大小与 SHA256，H.264/HEVC SPS VUI 的范围、原色、矩阵和传递函数。未声明、损坏、未支持语法分别记录；不伪造默认值。
- 实际解码器、配置实例及代次、首帧状态、输出颜色字段及完整格式描述、正式配置与基本性能计数。API28 未匹配已知平台软件前缀时记录未知，不认定硬件加速。
- 正式纹理路径分别保存原始纹理和隐藏控件后的窗口图，直接路径保存 Surface buffer。截图不代表物理面板、背光或最终硬件后处理。
- 截图前后摘要、实例或代次改变会标记并保留前置证据；旧请求、失败后的旧快照不归入新项目。正式结果必须等待连接关闭流程结束才消费，关闭未确认或中断不自动推进。
- ZIP 含 report.txt、observations.json、fixtures.json 和逐次唯一截图；每项证据/缺项与截图名称关联。旧版 v1 私有记录和截图未删除，新流程使用独立 v2 存储。
