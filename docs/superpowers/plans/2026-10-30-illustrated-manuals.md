# DiPlay 双册图文说明书实施计划

**Goal:** 为当前0.2.26/45 Flyme分支制作日常使用及独立测试诊断PDF，并在README首页提供入口。

**Architecture:** 当前可达界面和资源文案为事实来源，按功能逐项列入口、步骤、效果、生效时机与限制；保留Markdown正文、功能来源清单与可重复构建脚本。截图使用本轮Robolectric界面产物，明确标注不是实车截图。

**Tech Stack:** Python ReportLab、Arial Unicode中文嵌入字体、PDFKit渲染、pypdf内容检查。

## 已确认设计

用户已确认完整双册结构。日常册包含安装准备、主页、有线/无线、投屏操作、连接/显示/音频/导航/车辆/高级、故障排查。测试册包含方控、MFi、UID、解码/颜色/清晰度、手工采集、自动诊断与报告。A4纵向，目录/页码/索引，截图及正文均不冒充实车验证。

## 约束

- 仅编写手册、生成工具与README链接，不改应用逻辑、不升版、不安装。
- 首页指项目根README；交付文件位于output/pdf，正文与图片位于docs/manuals。
- 不纳入本地认证材料、个人信息、私密路径或未引用图标素材。
- 完成全部作者修改后统一验证；文档工作不重复无关Android全量测试。
- 当前任务未要求提交/推送，不自动提交或推送。

## 制作步骤

- [ ] 盘点所有实际可达功能，核对每个设置的效果与生效时机，记录源码依据。
- [ ] 核验并复制截图，覆盖普通首页/设置以及四类测试页面；图片注明来源。
- [ ] 撰写两册完整Markdown及条目化功能清单，保留条件显示/设备依赖说明。
- [ ] 创建可重复生成脚本，生成带目录、页码、截图和索引的两份PDF。
- [ ] 渲染全部PDF页面，逐页检查中文、布局、截图清晰度、溢出和空白。
- [ ] 验证正文覆盖、PDF文本/页码/链接、README路径与Git差异，交付PDF。

## 验证标准

每个正文功能条目均包含入口、操作、效果；涉及重连/权限/实验性的条目有明确说明。测试功能独立成册，日常册只提供测试手册入口。PDF无方框字、重叠、截断、空白尾页；截图可辨识且有图注；两条README入口均指向存在且可解析的PDF。
