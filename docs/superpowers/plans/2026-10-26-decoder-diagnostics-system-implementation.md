# 解码诊断系统改造实施清单

**目标**：落实同日系统设计，统一一键执行、隔离解码、同源输入、四维状态与验证后的 Download 交付。

**架构**：主进程前台 Service 持有运行状态与超时；独立 `:decoder_diagnostics` 进程运行标准片／同源回放和封存发布。执行进程通过 Messenger 汇报，超时可回收，不让页面拥有流程。现有手动工具保留。

**约束**：Android 9/API 28；版本保持 0.2.24/43；所有代码完成后统一测试；不自动提交；不修改日常视频、HFP、USB、方控设置。

- [x] 运行模型：稳定 run/case/source 标识、持久日志、四维结果、进程中断恢复与重新发布。
- [x] 独立主控／执行进程：前台通知、Binder 身份、单项与总预算、取消、晚回调、执行进程回收、页面退出不持有测试状态。
- [x] 标准输入：完整 2×2 与两条 YUV 路径；浅／深与全／有限范围成对素材、独立 FFmpeg 参考；1080p 清晰度与受控运动；预热、测量、截图分离。
- [x] 真实输入：限额捕获压缩访问单元、CSD、关键帧边界、时间戳与配置变化，原字节回放，缺失明确标识。
- [x] 关联证据：接收、提交、解码输出、YUV、Surface 时序，负载时间序列，请求／实际路径、截图几何、H1 高光裁剪模型误差与局部灰阶。
- [x] 发布：内部封存、ZIP 重读校验、公共临时文件、SHA256 校验后原子改名、独立异步下载登记；重导出不重测。
- [x] 页面：开始／停止、当前阶段、结果与证据缺口、实际文件路径、重新发布；手动诊断禁止与自动运行重叠。
- [x] 统一验证：状态故障注入、采样与回放边界、颜色数值反例、报告损坏与恢复、CI 五项；明确未做 Android 9 原生／实车验收。

真实 CarPlay 的浅深主题不强制操控，记录实际可确认依据；无可靠依据保持 unknown。实时静态证据不冒充运动或触摸延迟。物理面板测量不属于软件截图能力。

实施与已完成验证见 [验证记录](2026-10-27-decoder-diagnostics-system-validation.md)。代码实施与硬件验收分开：目标 API 28 原生、连接 iPhone 的捕获／回放及物理面板验收未标为已验证。
