# Flyme EAS 方控集成计划

目标：以实车验证的 carplay-wheel-replica-demo 为协议基线，将 Flyme EAS 接入 DiPlay；协议、焦点生命周期、诊断及 UID 构建均独立维护。

1. 为会话停止、晚到事件、有限焦点申请、源切换和按键映射建立纯 Java 回归测试。
2. 新增 integrations/flyme-eas Android library，保留已验证 Binder ABI，不带入 demo 的 UI、服务或凭据。
3. 新增 common/FlymeWheelIntegration.kt，挂接既有媒体会话生命周期与元数据监听；复用 iPhone sendMediaButton。
4. UID 构建通过单独 Gradle 脚本显式开启；普通构建保持安装身份且不接管 EAS。
5. 独立文档列出上游合并接点、构建及实车验收；执行单元测试、CI 检查并进行代码审查。

停止条件：有限的代码接点完成、退出不重抢、普通构建不介入、测试通过；构建环境限制与待实车项目明确记录。无新设置页面、无 MediaBridge 常驻策略、无私钥入库。

## 实施结果

- 已新增独立 :flyme-eas 模块及 DiPlay 适配器，现有媒体/前台/无障碍入口只增加小接点。
- 系统构建显式生成 main Manifest，保留普通身份和原 debug/release overlays；密钥未进入仓库。
- 10 项纯 Java 测试通过；模块 Java 编译通过；UID 构建脚本的 Gradle/AGP API 单独编译通过；Manifest 合并样例验证通过；diff 空白检查通过。
- 已进行独立代码审查并修正焦点请求积压、MediaController 控制误拦和 debug Manifest 被覆盖的问题。
- 完整 CI 与 APK 构建被环境 socket 权限拒绝阻止，尚未产出集成版 APK，尚未实车验证；详见 integrations/flyme-eas/README.zh-CN.md。
