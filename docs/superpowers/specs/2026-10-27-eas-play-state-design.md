# EAS 播放状态通知设计

用户已在查看 updatePlayState 链路说明后明确授权适配。目标是补充媒体中心独立播放状态通知；不能承诺解决内部状态缺失或厂商显示问题。

选择在现有 flyme-eas 模块内增加可降级状态通道，复用现有身份门槛与会话生命周期。相较把新事务串进方控工作线程，独立线程避免厂商调用阻塞原有按键；相较替换媒体中心注册，仅补充通知能保留已验证的封面/歌曲发布。无设置、无版本变更、无 HUD/25款星瑞逻辑。

使用 Framework init mediacenter / MediaCenterAPI.updatePlayState，包名取运行应用、displayId=0、播放1/暂停0。只转发 PlaybackSnapshot.playing，不猜测 iPhone 状态。保留最新值、成功去重，首次绑定/重连强制补发；失败按1/3/10秒退避重试。4秒看门狗使晚到返回失效，但不能取消Android Binder；不堆积新工作线程。停止会话后阻断所有普通发送，串行尽力发暂停、立即释放绑定；跨实例只允许最新会话发送，旧在途调用返回后强制新会话重发，避免旧停止覆盖。初始化靠interface token校验，不另作无看门狗的同步descriptor查询。

诊断写入现有 Flyme report/DetailedDebugLog：绑定、首次失败、拒绝code、成功playing、停止未送达/返回结果。code200仅代表接口受理。Android9/API28兼容。

验收：API28原始Parcel协议、播放→暂停→播放、同状态去重、首次连接补发最新值、服务断开重连、绑定失败重试、拒绝不作成功去重、迟到/关闭回调无效、停止最终false，原媒体注册/方控回归；全部代码完成后统一执行项目CI。实车最终图标仍待验证。
