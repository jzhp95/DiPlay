# CarPlay 灰阶截断证据与颜色／跟手性验收约束

- 日期：2026-10-31。
- 目标：同一实际投屏路径同时做到颜色正常、操作跟手。
- 结论级别：旧固定素材的部分软件直出路径已确认存在灰阶合并、亮部截断；最新版所有发白路径的具体责任环节仍未定位。
- 本文记录证据与约束，不代表颜色回归已经修复或实车验收通过。
- 顶级约束：[根目录 AGENTS.md](../../../AGENTS.md)。

原本不同的近白灰阶被合并成纯白，近黑灰阶也存在被压成黑色的情况。
这属于范围拉伸后发生截断，能够解释“浅灰与白色混在一起、亮部看起来发白”。

在这些已知 Full 范围素材上，结果高度符合以下错误扩张形态：

    output = clamp((input - 16) * 255 / 219, 0, 255)

两个用例的模型比较结果相同：

| 报告字段 | 数值 |
| --- | ---: |
| correctModelMeanAbsoluteError | 13 |
| expandedLimitedModelMeanAbsoluteError | 0.0724070450097847 |

h1Priority 为 repeat_limited_expansion_shape_supported。
它支持输出存在不应出现的 Limited 范围扩张形态，不能单凭模型名称
断言一定发生了两次转换，也不能定位转换究竟发生在哪个组件。

这项判断以输入素材、参考灰阶和截图三者一致为前提。
Limited 输入合法地从 16～235 映射至 0～255，不能照搬上表判成错误。

## 3. 已确认的现象与尚未确定的根因必须分开

已经确认：

1. 上述历史固定素材用例发生了灰阶合并和高光截断。
2. 这种输出形态与错误的 Limited 扩张模型高度吻合。
3. 报告覆盖了软件解码器的 Texture 与 Surface 两条直出路径。

尚未确定：

1. 错误转换由解码器、输出 Surface 转换、显示合成还是应用配置触发。
2. 最新版每一个发白组合是否都与历史用例属于同一机制。
3. 导致“软件直出早期正常、最新版发白”的具体版本差异或提交。
4. 不同编码、矩阵、范围、分辨率和输出路径是否受到同样影响。

SPS、MediaFormat 的颜色标签和实际解码后的像素数据必须分别记录；
参数标签正确不能证明最终像素正确。
灰阶测试通过是颜色验收的必要条件，不能替代彩色色块、矩阵及实际画面的验证。

## 4. 用户最新反馈作为回归调查线索

以下是用户实车观察，应与历史固定素材数值分开记录：

| 路径 | 用户反馈 |
| --- | --- |
| 早期版本：软件解码＋直接输出 | 颜色正常 |
| 最新版本：软件解码＋直接输出 | 发白 |
| 最新版本：软件 YUV＋跟随视频 | 颜色正常 |
| 最新版本：软件 YUV＋强制 Limited | 发白 |
| 最新版本：硬件 YUV＋跟随视频 | 发白 |

早期正常版本的精确 APK 哈希及最新版差异尚未完成对齐，不能虚构回归提交。

调查应优先比较曾经正常的软件直出路径，核对实际解码器、颜色参数、
渲染计划覆盖、Surface 类型和后处理变化。
软件 YUV＋跟随视频目前是用户确认颜色可接受的对照基线；
不能把它“颜色正常但仍不跟手”视为最终交付，也不能将尚未验证颜色正确的
硬件 YUV 自动提升为默认解决方案。

最新 QWERTY 目录中的 9 个 ZIP 在本次检查时均为 0 字节，不能作为最新版
像素诊断证据。应优先保留并恢复应用内已采集结果，不以反复要求用户重测替代定位。

## 5. 后续修改与验收必须满足的要求

1. 同一已知参考、同一帧及可比配置下，对齐源参考、解码后原始 YUV 和输出 RGB；
   记录实际 decoder、尺寸／crop、输出路径、颜色配置、版本身份和回退状态。
   独立无 Surface 解码实例必须标明，不能冒充被测实例的原始像素。
2. 对 Full 与 Limited 分别验证近黑、近白及彩色色块，防止不应发生的灰阶合并、
   黑白剪切和矩阵偏色；误差容限必须有依据，不能临时编造“通过”阈值。
3. 修复错误发生前的范围／矩阵解释。禁止用整体调暗、亮度／对比度滤镜或
   把已经截断的纯白压回浅灰来宣称恢复细节；截断后丢失的灰阶无法靠后处理还原。
4. 不得仅凭 SPS 为 Full、MediaFormat 标签正确、截图文件存在或单元测试通过，
   宣称实车颜色正常；也不得将所有画面一律强制为 Full、Limited 或 BT.709。
5. 颜色与跟手性必须在同一实际路径验收。队列到输出、纹理上传、交换缓冲和
   输入写出耗时分别报告，不能将其中一项称为完整触摸到显示延迟，
   不能用平均帧率代替卡顿／跟手性结论。
6. 保留历史正常路径作为回归对照。任何解码器、颜色策略或渲染路径调整，都需
   检查它是否重新引入灰阶截断；未验证的路径保持实验状态。
7. 报告必须分清“已确认现象”“模型支持”“待定位责任环节”“用户观察”和
   “已完成验收”，不得因最新日志缺失而否认历史像素证据，也不得据旧样本
   宣称最新版所有模式的根因已闭环。
