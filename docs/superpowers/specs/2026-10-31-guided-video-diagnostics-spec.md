# DiPlay 精简素材测试与真机引导式批测 Spec（含发白对比度与低延迟管线增强）

- 日期：2026-10-31（2026-11-01 修订）。
- 状态：修订版设计规格（已吸收实车地图实拍发白对比度分析、强制有限范围对照组及低延迟渲染管线优化）。
- 本轮范围：完善真机引导批测与测试方案，落实软件 YUV 零等待与积压判鲜生产优化，执行全量门禁与回归验证。
- 引导批测模式：硬解纹理、硬解直出、软件直出、软件 YUV 跟随、软件 YUV 强制有限范围（发白对照组）、MTK YUV。
- 目标环境：吉利星瑞 2026 款昆仑，Flyme Auto，Android 9／API 28，arm64-v8a。
- 应用版本保持 0.2.26／45；不因本方案自行升级。
- 顶级约束：[AGENTS.md](../../../AGENTS.md)。
- 颜色证据基线：[灰阶截断证据与验收约束](2026-10-31-carplay-grayscale-clipping-evidence.md)。
- 既有修复规格：[颜色、延迟与重连规格](2026-10-31-carplay-video-color-latency-remediation-spec.md)。

## 1. 用户目标与本方案承诺边界

最终产品目标是同一实际投屏路径同时满足“颜色正常＋操作跟手”。

本功能的交付目标是：用户分别选择素材测试或真机测试；真机测试选择一次 HEVC 开／关，
点击开始后由程序逐组准备模式、连接、提示操作、采集并保存；用户点击“结束本组并切换”
后，程序保存当前证据、断开旧连接、等待真实释放、切换到下一模式并重新连接。
用户无需手动改五套设置或反复寻找采集入口。

这是一套可恢复、可审计的采集和比较工具，不承诺自动修复颜色、不承诺完整触摸延迟
能够仅靠协议日志测出，也不能把“运行结束”显示成“所有模式验收通过”。

### 1.1 范围内

- 保留两个独立入口：精简内置素材测试、真机五模式引导测试。
- 精简素材为灰阶、彩色色块、短运动视频三类，保留 Full／Limited 与必要矩阵覆盖。
- 当前版本的五种实际投屏路径，不安装或切换旧版 APK。
- 真机每轮固定一种请求编码策略：HEVC 关闭或开启。
- 真人操作，程序自动提示、采集、保存、断连、切模式及重连。
- 实际路径核验、同帧颜色证据、分段输入／视频时间线、CPU／帧率／积压证据。
- 每组独立持久化；取消、进程退出或后续失败不得抹掉已完成组。
- 原设置恢复、最终报告重发、文件大小和哈希回读校验。

### 1.2 范围外

- 当前 App 自行卸载、降级或替换自身来切换旧版；旧版 APK 仅作为单独的历史对照。
- 自动操纵手机应用来保证某张参考图一定能够出现在 CarPlay 中。
- 以车机原生叠加参考图冒充“手机视频流包含已知参考图”。
- 默认自动发送 HID 拖动代替用户实际手指操作。
- 自动启动另一台手机的录像、伪造手机 ACK 或推算未取得的物理呈现时间。
- 用自然地图画面的最小／最大值自动猜 Full／Limited，再据此强制校正。
- 将局部 11.7ms 或平均帧率宣称为完整跟手性达标。

## 2. 选择的总体方案

采用“素材测试独立运行＋正式会话中的真机引导批测”。

两种可选替代方案及取舍：

| 方案 | 优点 | 不采用的原因 |
| --- | --- | --- |
| 所有组都在独立播放器回放 | 易复现、易对齐像素 | 不能替代真实 CarPlay 连接、输入与网络链路 |
| 只保留当前手动改设置采样 | 改动少 | 容易漏改配置、混组、漏保存，不能满足自动断连切组 |
| 独立素材入口＋真机引导批测 | 同时保留复现能力和真实链路 | 本方案采用；两类结果必须明确标识 |

复用既有 SessionRuntime、DiagnosticLease、持久化存储与发布组件，不在页面另起一套连接控制器。
真机批次由协调器持有，Activity 只显示进度和收集用户操作；不得把长任务放在 Activity 计时器里。

## 3. 测试入口与页面结构

“解码测试”中保留两个明确入口：

1. “内置素材测试”：不要求连接 iPhone，不捕获真实手机内容。
2. “真机五模式测试”：需要已配对且可连接的 iPhone，不自动混跑素材矩阵。

真机入口包含：

- HEVC 开关，默认关闭；开始后锁定到本轮结束。
- 固定五模式列表、预计操作步骤、当前采集能力说明。
- “开始五模式测试”。
- “恢复／重发上次报告”，不要求重跑采样。
- 非活动状态才允许清理测试记录，且不得删除未交付的原始证据。

每轮只执行五组，不因 HEVC 开启扩展为十组。
若要比较 H.264／HEVC，应分别运行两轮，明确生成不同 runId。

页面始终分开显示：

- 执行进度。
- 已完成与未完成组。
- 私有证据保存状态。
- 公共目录交付状态。
- 颜色可判定程度。
- 性能数据有效性。
- 用户手感记录和客观完整触控延迟是否可用。

## 4. 引导测试模式的固定定义（含发白对照组）

建议按颜色基线、发白对照、回归路径、低延迟目标、其他路径的顺序执行：

| 顺序／profileId | 用户名称 | 解码要求 | 输出要求 | 颜色策略与对比目的 |
| --- | --- | --- | --- | --- |
| 1／software_yuv_auto | 软件 YUV＋跟随视频 | 确认平台软解，禁止硬解替代 | 应用 YUV→EGL | 范围／矩阵跟随声明，保留解析依据（当前基线） |
| 2／software_yuv_limited | 软件 YUV＋强制有限范围 | 确认平台软解，禁止硬解替代 | 应用 YUV→EGL | 强制 Limited Range(16~235)＋BT.709展开；专治 iPhone SPS 虚标 Full 导致道路发白消失 |
| 3／software_direct | 软件解码＋直接输出 | 确认平台软解 | SurfaceView 直出，不进入 YUV 自绘 | 解码器原生声明语义，无额外手动范围覆盖 |
| 4／hardware_surface | 硬解直出 SurfaceView | 确认目标车机硬解组件 | SurfaceView 直出 | 解码器原生声明语义，无额外手动范围覆盖 |
| 5／hardware_texture | 硬解纹理输出 | 确认目标车机硬解组件 | TextureView，记录实际路径 | 解码器原生声明语义，无额外手动范围覆盖 |
| 6／mtk_yuv_auto | 硬解颜色转换 MTK YUV | MTK 硬解，取得 Image | 应用 YUV→EGL | 范围／矩阵跟随声明，保留解析依据 |

> [!IMPORTANT]
> **增设 `software_yuv_limited` 的数学与生理依据**：
> iPhone 在 H.264 VUI 中常态化声明 `video_full_range_flag = 1`（`hints={color-range=1}`）。
> 在“软件 YUV 跟随视频”模式下，Shader 认为输入已是 0~255 全范围，采用 $Y_{\text{offset}} = 0, Y_{\text{scale}} = 1.0$。
> 但若实际视频编码信号动态范围受限于 16~235（或车机显示屏后端驱动将 EGL 输出按有限范围二次映射），未进行 $(Y-16)\times\frac{255}{219}$ 展开时，
> 信号黑位停留在 16（发灰）、高光压缩在 235（灰白），导致全图对比度严重被挤压在中间区域。实车实测高德地图白色背景（$Y \approx 207$）与灰白道路（$Y \approx 213$）色阶差仅 **5** 个灰阶，道路轮廓彻底湮灭在白底中。
> 增设 `software_yuv_limited` 对照组强制展开动态范围（16 映射到 0 纯黑，235 映射到 255 纯白），能够闭环验证地图道路反差是否立即恢复。

所有组均为当前同一 APK。没有“在当前 APK 中模拟旧版本”这一组。

各组不是只切换按钮状态，必须验证实际 decoder、实际输出、YUV 是否启用、
是否发生回退，以及配置哈希。请求软解却实际使用硬解、请求 MTK YUV 却已回退到直出，
均不得计为该组成功。

Android 9 上不得无版本保护使用 API 29 才有的硬件／软件组件识别接口。
组件名称推断、平台软件组件名单与实际 API 返回必须分别记录其依据。

### 4.1 控制变量

每组固定：

- 同一手机、iOS、应用 APK、连接方式、目标显示区域、请求分辨率和帧率上限。
- 同一 HEVC 请求设置、音频策略、MTK tuning、低延迟选项。
- 相同地图应用、日夜主题、地点和缩放级别；由用户按提示恢复场景。
- 车机亮度、日夜模式和已知显示增强设置。
- 除 `software_yuv_limited` 显式强制有限范围外，其余组无额外手动范围覆盖。

允许改变的因素只限 profile 定义所需的解码／输出路径与颜色显式映射策略。
“原生解码器处理元数据”和“应用 Shader 处理元数据”必须分开命名，
不能因为 UI 都显示“跟随视频”就假设实际转换完全相同。

其他设置在测试中被外部修改时，当前组标记条件改变并暂停；不静默覆盖用户的新设置。

## 5. HEVC 请求与实际协商

- 关闭：本轮要求实际 H.264；若仍为 HEVC，停止该组并报告实际编码不匹配。
- 开启：本轮以 HEVC 对照为目的，必须检查实际为 H.265，不能把开关打开但仍收到
  H.264 的结果混入 HEVC 对照。
- 手机未选择 HEVC时，可重试一次；仍不匹配则暂停或标记协商不匹配，由用户选择跳过。
- 某软解组件不支持 HEVC，标记该 profile 不支持，不允许偷偷改用 H.264 或硬解完成。
- 新会话 SPS 到来后核验实际编码、矩阵、范围与源尺寸；只看设置值不算核验。
- HEVC 比较中若颜色声明、实际帧率、MTK tuning 或其他条件同时变化，应列出混杂项，
  不将全部差异归因于编码器。
- maxFPS 是上限声明，不代表手机实际选择或持续输出该帧率。

## 6. 精简素材测试

### 6.1 三类素材与最小默认集合

“只保留三类”不等于用一张灰阶图覆盖所有范围和矩阵。
真机 HEVC 开关不隐式改变素材计划。本版默认素材使用 H.264，不混跑两种编码；
HEVC 素材属于显式单独启动的专项，未提供对应素材与校准时须标明不覆盖。

| fixtureId | 类型 | 必须覆盖的内容 |
| --- | --- | --- |
| G_FULL | 灰阶 | Full 参考；近黑 0、4、8、12、16、20；中灰；近白 224～255 的可区分阶梯 |
| G_LIMITED | 灰阶 | Limited 参考；验证合法范围扩张，不误判为 Full 截断 |
| C_FULL_601 | 彩色色块 | Full＋BT.601 系数，覆盖手机曾出现的 primaries=1、matrix=6、transfer=13 声明组合 |
| C_FULL_709 | 彩色色块 | Full＋BT.709，红绿蓝、青品红黄、白黑及中性色 |
| C_LIMITED_601 | 彩色色块 | Limited＋BT.601，验证色度范围和通道解释 |
| M_1080_60 | 短运动视频 | 已知 PTS、1080p60、运动边缘和帧序号；检验帧节奏、积压及跳帧 |

默认六个 fixture × 五条路径，共三十个用例。
若某素材尚不存在，可在后续实施时生成并验证同类小素材；本轮不生成或修改任何素材。
优先复用现有资源，不重复打入大视频，不改变 APK 的架构和版本号。

这不是覆盖所有范围／矩阵／编码的穷举矩阵。
未覆盖组合须在报告 coverage 中列明；例如 Limited＋BT.709 属于专项扩展，
不能因默认用例通过就宣称所有矩阵组合通过。

每个素材必须有版本化清单：文件 SHA256、实际 SPS、范围／矩阵／transfer、
尺寸、帧率、帧索引、patch 几何、重建参考值和误差容限的校准依据。
不得仅凭文件名 full／limited 推断实际参数。

### 6.2 素材执行

- 正式 CarPlay 正在运行时，明确提示素材测试会临时占用视频解码，保持两类测试互斥。
- 每例使用独立身份；按已知随机访问帧输入，固定采样帧，采集颜色与时间线。
- 颜色 fixture 必须采近黑、近白和彩色区域，不只取默认屏幕中心三点。
- 静止画面不用于宣称动态流畅；运动素材不替代真实手机输入链路。
- 每例独立落盘；失败可继续其余不依赖该资源的用例，但真实资源未释放时必须暂停。
- Full 235、236、238、240 被不当合并为 255 等已知故障，检测器必须能识别。
- 对无异常模型支持只能报告“该模型未支持”，不能自动写“颜色全部正常”。

## 7. 真机逐组操作向导

### 7.1 开始前预检查

首次点击开始时，在不改变连接前检查：

- 没有素材测试、其他真机批次或资源退役阻塞。
- 目标手机已选择、配对可用、所需权限具备。
- 持久化存储与最终报告读取路径可用；检查可用空间。
- 用小型临时归档验证写入、同步、原子提交及回读；不得只调用 mkdirs。
- 用户原视频设置与原连接状态已原子保存，且得到持久化成功确认。
- 当前版本具备所选编码和五模式的实际能力核验。
- 明确告知本轮颜色取证等级，以及完整触控延迟是否需要外部录像。

预检查失败即停止，不先让用户操作完再告知采不到数据。
只为本轮诊断申请必要权限；不变更热点密码、配对信息或系统显示偏好来强行通过。

### 7.2 每组进入

程序执行：

1. 提交本组纯内存运行态配置快照（RuntimeOverride）。
2. 完成上一会话的真实资源释放，并确保满足 Wi-Fi / 热点协议栈 3~5 秒静默窗口。
3. 通过正式 SessionRuntime 启动新会话，不新建平行控制器。
4. 等待实际视频输出、decoder／codec／profile 核验完成。
5. 从首个有效输出之后开始预热，默认至少两秒，预热数据不纳入正式统计。
6. 显示本组编号、请求／实际模式、编码与操作提示。

不采用固定 sleep 后直接宣布连接成功。
不满足条件时不开始统计；无法确认实际路径时显示未确认。

### 7.3 颜色阶段

提示文案：

    第 2／6 组：软件 YUV＋强制有限范围，H.264
    请展示约定参考画面或自然地图主视区，保持主题、缩放和亮度一致。
    已准备好后开始颜色采样。
    若无法在 CarPlay 显示参考图，可采样自然地图主视区进行边缘反差量化。

颜色阶段默认二十秒，允许提前结束，但报告短采样原因。
参考图确认是操作确认，不是手机内容已经被数学验证的证明。

颜色阶段必须明确采用以下哪种来源：

| 来源等级 | 可输出的结论 |
| --- | --- |
| 手机真实 CarPlay 流中已识别的参考图，几何和帧身份核验成功 | 针对该参考和测量边界的客观像素比较（灰阶阶梯与色块误差） |
| 自然地图主视区客观边缘反差量化 | 计算道路与背景的局部灰阶阶梯差 $\Delta Y$，输出 roadEdgeContrastScore |
| 已捕获的同一段真实码流，在被测路径重放并与有效参考解码对照 | 同源路径差异；必须标明是回放，不是实时投屏 |
| 普通地图截图和用户主观观察 | 用户颜色反馈；若未采样边缘反差且无参考图，绝对颜色状态为不可判定 |

> [!TIP]
> **自然地图场景下的 `roadEdgeContrastScore`（道路边缘反差评分）**：
> 针对车载用户高频反馈的“高德地图道路发白看不清”的真实场景，在无标准测试图卡输入时，程序在地图主视区自动提取道路边缘截面线，计算道路区域均值与邻近背景区域均值的灰阶差：
> $$\Delta Y = |Y_{\text{road}} - Y_{\text{background}}|$$
> - $\Delta Y < 8$：判定为 `low_contrast_washed_out`（极低反差／发白坍塌，如用户实拍照中 $\Delta Y \approx 5$，道路轮廓消失）；
> - $8 \le \Delta Y < 18$：判定为 `borderline_contrast`（偏淡，强光下可能难以辨识）；
> - $\Delta Y \ge 18$：判定为 `contrast_acceptable`（反差正常，道路轮廓分明）。
> 该指标打破了“无测试卡即无法定量评判发白”的死锁，为软件 YUV 跟随模式 vs 强制有限范围模式提供了直接的客观对比依据。

禁止将车机 App 自己绘制的参考图，当作已经穿过 iPhone 编码和 CarPlay 解码链路。
不能呈现参考图时，性能采集仍可进行，但 UI 必须提前显示颜色证据的限制。

### 7.4 操作阶段

提示文案：

    颜色采样已保存。
    请回到同一地图地点和缩放级别，连续左右拖动，再反向拖动。
    程序将记录真实触摸与视频链路；请完成约二十秒操作。
    完成后点“结束本组并切换”。

- 默认建议二十秒，计时只用于引导，不能替代检测实际拖动。
- 无拖动事件、视频无动态输入或采样过短，分别记录原因。
- 可提示补一个点按／缩放动作，用于区分持续拖动与单次响应。
- 用户操作期间不注入额外自动 HID 手势。
- 测试控制按钮必须消费自身触摸，不能同时传给手机成为地图操作。
- 用户可记录“颜色正常／发白／亮部合并／黑色发灰／偏色”，以及
  “跟手／持续滞后／间歇卡顿／无法操作”；主观记录独立保存。

颜色捕获、原始帧落盘等较重操作在颜色阶段完成。
进入操作阶段前再次稳定输出，避免把一次截图开销误算成常态手感。
仍须记录诊断开销和采集状态，不能宣称仪器完全没有性能影响。

### 7.5 结束本组并切换

点击按钮后必须按以下次序执行：

1. 锁定结束事件，拒绝重复结束和重复前进命令。
2. 停止本组计数窗口；等待已发起的截图／证据任务完成或明确超时。
3. 原子提交当前组数据和缺失原因。
4. 生成可独立读取的本组证据包，核验条目、大小和哈希。
5. 私有持久化确认成功后，才允许切断当前连接。
6. 公共导出可重试；其失败不能抹掉已验证的私有证据。
7. 请求关闭当前连接，等待真实释放完成。
8. 真实释放完成后，进入 3~5 秒 Wi-Fi／热点网络栈静默缓冲期，避免短时间高频 socket 释放与重连引发 TCP TIME_WAIT 端口竞争或手机端 AirPlay 服务崩溃。
9. 为下一 profile 构造全新 SessionStartRequest（使用纯内存 RuntimeOverride，禁止写入 SharedPreferences）并自动连接。
10. 核验新会话身份与实际输出，提示下一组。

提前结束时不能伪造完整采样：
组状态记录 partial 和具体缺口，数据仍保存。
已经提交的组只读封存；重试用新的 attemptId，不覆盖旧尝试。

### 7.6 一轮结束

- 最后一组执行相同保存与释放流程。
- 恢复用户开始前的设置，按开始前的连接意图决定是否恢复原模式连接。
- 开始前已连接：尝试恢复原配置并重连。
- 开始前未连接：恢复设置并保持断开。
- 用户选择“停止并保持断开”时，以该意图为准。
- 恢复失败显示“测试结束，设置／连接尚未恢复”，提供恢复入口。
- 所有已采结果保持可导出；不得只因最后恢复失败就删除整轮。

## 8. 状态机和连接归属

### 8.1 状态

主流程：

~~~text
IDLE
 → PREFLIGHT
 → SNAPSHOT_ORIGINAL
 → PREPARE_CASE
 → WAIT_OLD_RELEASE
 → CONNECTING
 → VERIFY_ACTUAL_PATH
 → WARMUP
 → WAIT_USER_READY
 → COLOR_CAPTURE
 → WAIT_USER_OPERATION
 → INTERACTION_CAPTURE
 → USER_FINISH
 → SEAL_CASE
 → VERIFY_CASE_ARCHIVE
 → NEXT_CASE 或 RESTORE_SETTINGS
 → RESTORE_CONNECTION
 → PUBLISH_BATCH
 → FINISHED
~~~

其他状态：

- PAUSED_USER：用户暂停，停止正式统计但保留会话和状态。
- PAUSED_CONNECTION：手机未连接、权限或配对提示需要用户处理。
- PAUSED_STORAGE：私有保存未确认；禁止进入下一组。
- BLOCKED_RELEASE：旧资源未实际释放；禁止叠加新会话。
- UNSUPPORTED_CASE：该编码／profile 不可用，可明确跳过。
- INTERRUPTED：进程退出、失去测试所有权或用户终止。
- FINISHED_WITH_GAPS：执行结束但存在缺失／不可判定项目。
- RESTORE_FAILED：原设置或连接未恢复。

### 8.2 强制不变量

- 一个批次同一时刻最多一个活动 case、一个目标手机会话。
- 同一 case 的采样不能混入另一 sessionGeneration 或 SurfaceGeneration。
- 旧回调到达时必须根据 runId、caseId、attemptId、generation 拒绝写入新组。
- 超时不等于资源已释放；BLOCKED_RELEASE 不允许强制清空标志后重连。
- 保存失败不能断连前进，不能用内存中的 JSON 冒充已持久化。
- 配置切换必须严格采用纯内存会话快照（RuntimeOverride），严禁写入持久化 SharedPreferences。若在切组中途车机意外熄火、断电或应用崩溃，持久化配置依然是用户日常设定，杜绝残留污染。严禁只修改 SharedPreferences 再对旧请求调用 reconnect 假装切组。
- 测试结束后旧的自动重试／定时回调不得覆盖用户手动连接或设置。
- 测试租约和生产会话代际分开管理。不能跨五次重连复用绑定旧 sessionToken 的 Ticket。
- 复用并扩展既有 DiagnosticLease 的归属检查；不引入绕过它的并行诊断通道。
- 真机批测不能持有 blocksProduction=true 的旧租约，反过来阻止下一组的正式连接。
- Activity 旋转／重建只重新绑定状态，不重新启动批次或重复提交“结束”。

## 9. 最小完整数据契约

### 9.1 身份与环境

每轮和每组记录：

- schemaVersion、runId、caseId、attemptId、profileId、时间和本机单调时钟基准。
- APK SHA256、versionName／Code、是否 R8、映射身份引用。
- 手机型号、iOS（用户填写则注明来源）、车机型号、API、ABI。
- 请求／实际编码、decoder 组件及识别依据、实际输出路径、回退原因。
- 请求／实际尺寸、crop、stride、位深、源 PTS 节奏、到达和输出节奏。
- 连接方式、可获取的网络信息、温度／降频状态及采样可用性。
- 本组配置快照及 SHA256；不包含热点密码、配对密钥或认证输入。

### 9.2 颜色证据

对已知参考、同源比较帧或自然地图记录：

| 层次 | 必需内容 |
| --- | --- |
| 输入 | CSD／SPS、解析状态、range／matrix／primaries／transfer、源段哈希、随机访问点 |
| 帧绑定 | AU 标识／哈希、输入 PTS、输出 PTS、实例、代际、捕获位置 |
| 原始 YUV | 实际 Image 采样位置、plane rowStride／pixelStride、crop、Y/U/V 码值、位深 |
| 输出 RGB | 原尺寸无损捕获、捕获来源、像素格式／可用颜色空间说明、ROI 几何 |
| patch 指标 | 参考和实测逐通道均值、最小／最大、饱和比例、相邻灰阶差 |
| 边缘反差量化 | 自然地图道路与背景灰阶阶梯差 $\Delta Y$（roadEdgeContrastScore）、采样线数量、对比度判定 |
| 转换解释 | 请求策略、实际采用的范围／矩阵、选择依据、EGL／Shader 配置身份 |

Surface 直出不能直接取得同一实例的 Image。
独立无 Surface 解码是辅助对照，必须记录不同实例和配置差异，
不能标为原 Surface 路径完整三层取证，也不能据此定位到某个具体内部组件。

能获取 Surface 输出 RGB 与最终窗口 RGB 时，两者分开记录。
实际 buffer／Surface dataspace 无法获取时应标为 unavailable，不从 SPS 反推填入。
屏幕照片只辅助检查面板／后处理，不能当作原始视频 RGB 或定量校色参考。

检测指标：

- 近白和近黑的多级合并、饱和比例、局部对比度。
- Full／Limited 正确模型和错误扩张模型的残差。
- 中性灰偏色、彩色色块误差及 UV 交换形态。
- 参考解码的重建像素和容差依据，而非只使用编码前的理想值。
- 自然地图场景计算道路边缘阶梯差 $\Delta Y$，直接检测高光低对比度与道路轮廓发白（$\Delta Y < 8$ 为 washed_out）。
- 普通地图在未采样边缘反差且没有已知参考时，不自动依据均值宣称发白或正常。

### 9.3 输入与视频时间线

同一本机时钟下记录：

| 路径 | 事件 |
| --- | --- |
| 输入派发 | Android 原始事件时间、应用收到时间、时钟转换依据 |
| 本地输入 | 入队、出队、排队年龄、合并／拒绝、手势与 pointer 集 |
| 写出 | event 写锁等待、实际 write／flush 开始和结束、失败 |
| 视频输入 | 原始包到达、AU 完成、入解码队列、出队、输入 buffer 获取及提交 |
| 视频输出 | 输出出队、YUV 拷贝、纹理上传、绘制、swap 或 Surface 提交 |
| 积压恢复 | 帧／字节深度、最老帧年龄、参考链状态、关键帧请求、丢帧和 codec 重建 |

记录均值、P50、P95、P99、最大值和有效样本数；无样本为 null，不填 0。
CPU 包含进程单核等效值、关键线程 CPU 时间与对应墙钟时间；
不将进程 CPU 当成某颗核占用，不将 codec 等待当成纯 CPU 解码耗时。

源手机时钟与本机时钟未映射时，禁止相减得到单向网络时延。
写出完成不是手机响应，swap 返回不是面板完成呈现。
不能用平均帧率替代长间隔、积压或实际跟手性。

> [!TIP]
> **软件 YUV 低延迟渲染管线优化规范**：
> 1. **消除 VSync 等待**：`SoftwareYuvRenderer` 在 EGL 环境创建后显式执行 `EGL14.eglSwapInterval(display, 0)`，使 `eglSwapBuffers` 立即返回非阻塞排入 SurfaceFlinger，彻底消除 16.6ms 锁步等待。
> 2. **积压感知丢弃（Backlog-Aware Skip）**：`VideoOutputFreshness.shouldDiscardDecodedOutput` 接入输入队列积压感知（`hasPendingBacklog = queue.backlogAfterCurrent().pendingFrames > 0`）。当工作线程发生抖动导致帧年龄超标且后续已有新帧就绪时，主动跳过已解码陈旧帧的 CPU YUV 内存拷贝与 OpenGL 纹理上传（保留 MediaCodec DPB 解码参考链完整），直接释放缓冲。工作线程瞬间吸收队列尖峰，彻底根治多帧排队延迟导致的“不跟手”。

### 9.4 完整跟手性与外部录像

程序记录真人操作，但没有可靠的手机响应 ACK 和触摸→画面因果对应时：

- phoneAcknowledged = unknown。
- causalFrameAssociation = unavailable。
- touchToPhotonMs = null。

可选外部高速录像须同时拍到手指接触和对应画面变化。
记录录像帧率、文件哈希、组别、触摸帧与响应帧、人工标注依据和测量误差。
整轮录像可以覆盖五组，画面角落显示组别便于归属，不要求五次重新拍摄。

没有录像不阻止收集局部性能和用户手感；但完整触摸延迟不得标为已测或通过。

### 9.5 真机源流与采集扰动

- 每组保留有界短段真实视频流、CSD、AU 索引及时间戳，用于后续同源回放。
- 至少从随机访问点开始；预算耗尽前无法完成可回放 GOP，应标为不完整。
- 不将真机原始流静默上传；默认保存在本次诊断目录。
- 动态测量期间避免逐帧完整截图和无界 rawYUV 落盘。
- 记录采集期间发生的截图、写盘和诊断开销，使性能比较可解释。

## 10. 结果分类与界面措辞

每组必须分别输出：

| 字段 | 含义 |
| --- | --- |
| execution | completed／failed／unsupported／interrupted |
| evidenceCompleteness | complete／partial；同时输出字段级缺口 |
| pathValidity | confirmed／mismatch／unknown |
| colorMeasurability | known_reference／same_source_relative／observation_only／unavailable |
| colorVerdict | clipping_detected／reference_match／mismatch／low_contrast_washed_out／contrast_acceptable／not_determined |
| roadEdgeContrastScore | 自然地图道路与背景灰阶梯度阶梯差实测值 $\Delta Y$（无采样时为 null） |
| performanceValidity | valid／confounded／insufficient |
| userColorObservation | 用户主观颜色选择（正常／发白／偏色等） |
| userFeelObservation | 用户主观手感选择（跟手／滞后卡顿等） |
| touchToPhotonMs | 无可靠对应测量时为 null |
| restoration | restored／failed／not_required |
| delivery | private_verified／public_verified／failed／pending |

不能把 reference_match 扩写成所有颜色、所有输入、所有版本通过。
缺少校准容差或完整颜色证据时，不产生“颜色总验收 PASS”。
用户主观正常可以记录，但不得覆盖明确的像素异常。
五组运行完成不等于五组都有效，更不等于同时满足最终产品目标。

最终报告必须给出实际可比对照与混杂条件，而不是无条件推荐平均耗时最小的模式。

## 11. 落盘、归档与交付

### 11.1 目录与身份

拟采用独立 schema 的批次目录，复用已有存储／协调基础：

~~~text
guided-video/<runId>/
  run.json
  original-settings.json
  mode-matrix.json
  capabilities.json
  reference/manifest.json
  cases/<caseId>/<attemptId>/
    case.json
    input-events.ndjson
    video-events.ndjson
    queue-events.ndjson
    samples.json
    source/csd.bin
    source/segment.bin
    source/frames.json
    pixels/raw-yuv.json
    pixels/raw-frame.bin          # 可选，必须有真实实例与布局说明
    captures/color.png
    observations.json
    manifest.json
  checkpoints/<caseId>-<attemptId>.zip
  batch-summary.json
  delivery-receipt.json
~~~

manifest 包含每个条目的实际字节数和 SHA256。
ZIP 自身哈希放在外部 receipt，避免自引用哈希。

### 11.2 保存顺序

- 写临时文件、同步、提交、回读后才确认私有保存。
- 每组私有包可独立解析，即使最终汇总未完成也能分析。
- 最终 ZIP 流式生成，避免一次将全批原始视频与图片读入堆内存。
- 公共目录复制、下载登记／发布等操作全部完成后，再检查最终文件和分享 URI 的
  字节数、哈希及可读性；不能用私有源 ZIP 大小充当公开文件验证结果。
- 最终分享的是哪个实体文件、公共目录是哪份副本，须在 receipt 分别记录。
- UI 显示实际交付状态；公共失败但私有包有效时，显示“仅保留应用内副本，可重发”。
- 电脑收到文件后也需核对 receipt 的大小和 SHA256。车机回读成功不等于传输必然成功。
- 任何 0 字节、条目缺失或哈希不符均不能显示成功。

### 11.3 内存、磁盘和保留策略（支持动态存储预算）

以下为设计初始预算与动态扩容规则：

- **动态磁盘预算检查**：使用 `StatFs` 在测试前及每组结束动态查询内部存储可用空间。
  - 当可用空间 $\ge 2\text{ GiB}$ 时，将原始证据预算安全放宽至 $256\sim 512\text{ MiB}$，以完整记录短视频源流与完整 trace，不强行压缩采样；
  - 当可用空间在 $512\text{ MiB}\sim 2\text{ GiB}$ 时，沿用标准基线预算 $128\text{ MiB}$；
  - 当可用空间 $< 512\text{ MiB}$ 时，触发 `PAUSED_STORAGE` 警告，禁止开启新的大证据捕获。
- 活动短段码流缓存上限复用现有约 8 MiB 预算，不在内存中持有全批完整视频。
- 原始帧一次最多保留一个主采样帧和必要的有界异常证据；持续帧只保留时序和统计。
- 诊断自身新增驻留数据目标不超过 32 MiB，不包括平台 codec／GPU 分配，实施时需实测。
- 超预算只能停止非关键扩展、标明证据缺口或暂停；不得继续无界分配。
- 活动批次和未交付的原始证据不能被旧的“保留最近八个报告”逻辑静默清理。
- 不删除用户公共下载目录的历史报告来腾空间。

## 12. 失败、取消、超时和恢复

| 情况 | 必须行为 |
| --- | --- |
| 实际编码与请求不符 | 不开始有效采样；有界重试一次，随后暂停／明确跳过 |
| 所需组件不存在 | unsupported，记录组件枚举结果；不以其他路径充数 |
| 组内发生解码／输出回退 | 封存当前段并标路径失效；新路径若采集需新身份 |
| 断开或系统打断 | 保存已取得数据；暂停，用户决定重试或跳过 |
| 释放超时／native 未退出 | BLOCKED_RELEASE；保存状态，禁止启动下一 codec |
| 私有写入失败或磁盘满 | PAUSED_STORAGE；不得自动断连前进 |
| 公共目录／下载服务失败 | 私有包有效则保留并允许后续组；显示交付缺口，支持重发 |
| 用户暂停 | 关闭测量窗口，保留现场；继续时开启新段，不能跨暂停合成连续时延 |
| 用户停止整轮 | 保存当前 partial，释放资源，恢复设置及用户指定的连接意图 |
| App 进程被杀 | 下次启动显示恢复入口；不偷偷自动重连、重测或覆盖已完成组 |
| 恢复设置时用户又改设置 | 按字段修订号检测冲突，不覆盖后来的用户修改 |
| 截图超时或实例已变化 | 标明缺图／错帧，不把其他实例图拼成完整证据 |
| 最终汇总失败 | 五组独立包仍保留，可重新归档，无需重测 |

连接和释放期限复用正式运行时的权威状态。UI 可显示等待超时，
但不能自行认定释放成功。连接尝试默认最多一次自动重试，其余由用户选择。
颜色二十秒、操作二十秒、预热至少两秒属于引导默认值，不是颜色或手感通过阈值。
总耗时不能承诺固定数值，切组和手机确认可能需要额外时间。

## 13. 原设置快照与恢复事务（纯内存隔离）

需记录视频相关设置白名单：

- HEVC、软件 HEVC 偏好、软件直出、软件 YUV、软件 YUV 范围／矩阵。
- 硬件 YUV、直接输出、平滑视频、MTK tuning、低延迟、请求尺寸与帧率上限。
- 会话的其他不变参数指纹与开始前连接状态。

> [!IMPORTANT]
> **纯内存运行态隔离（RuntimeOverride）核心原则**：
> 引导测试中切换模式，严格通过内存中的 `SessionStartRequest.RuntimeOverride` 注入到会话中，**绝不调用 `SharedPreferences.edit()` 覆写持久化磁盘数据**。
> 这样即使车机中途断电、用户熄火离开或测试进程崩溃，下次上车启动 DiPlay 时读取的永远是用户原有的生产设置，完全免疫测试配置泄漏导致的日常连接画质或延迟倒退。

若必须借助持久设置，保存原值、测试值及修订号；恢复仅覆盖仍等于测试写入值且未被用户
后来修改的字段，不能用一份旧快照无条件覆盖整个设置文件。

恢复结果需要落盘；失败不写 restored。
用户下次启动可恢复尚未清理的测试覆盖，但必须明确提示，不启动新的测试。

## 15. 开发与验证顺序

以下是后续实施阶段，本轮不执行：

3. 接入会话重配置与真实释放，完成 UI 引导和设置恢复。

5. 精简素材矩阵并建立已知正确／错误的检测夹具。
6. 接入最终交付校验、每组独立包和离线分析。
7. 所有当前范围代码与测试用例写完后，再统一运行验证，遵守 AGENTS.md。
8. 软件门禁、报告实际读取和故障注入通过后，才安排一次有明确目的的实车验收。

不在编码过程中交替运行零碎测试；不把测试源码存在算作已经执行通过。
不因本 spec 已写完就修改测试状态或对外宣称功能可用。

## 16. 验收矩阵

### 16.1 开发机可完成的必需验证

| 场景 | 必须得到的结果 |
| --- | --- |
| 一次开始、连续五次结束 | 每组只提交一次，严格按顺序创建下一请求 |
| 请求软解而组件为硬解 | 路径不匹配，不能 completed-valid |
| HEVC 开但实际 H.264 | 编码不匹配，不混入 HEVC 对照 |
| 某模式 HEVC 不支持 | unsupported，不自动换编码完成 |
| 错误范围扩张 fixture | 检测到灰阶截断，报告样点与模型，不只断言字符串 |
| 正确 fixture 与合法 Limited 扩张 | 不误报为同一 Full 截断错误 |
| 灰阶通过但彩色色块错误 | 不得给出颜色总通过 |
| raw YUV／参考图／同帧身份缺失 | 对应缺口、partial 或 not_determined |
| Surface 直出＋独立 raw 对照 | 保留不同实例身份，不宣称三层同实例完整 |
| 保存中进程退出／磁盘满 | 已完成组可恢复，不前进、不覆盖原始数据 |
| 公共文件被清空／改写 | 最终回读失败，不能显示 public_verified |
| 分享 URI 不可读 | 不显示交付成功，保留私有源并明确错误 |
| 重复点击结束／迟到回调 | 幂等处理，不把上一组结果写进下一组 |
| codec 未释放 | 没有下一会话，状态为 BLOCKED_RELEASE |
| UI 旋转／返回再进入 | 同一 runId，不重复启动，不丢进度 |
| 用户中途改设置 | 恢复不覆盖用户较新的修改 |
| 缺少完整触控测量 | touchToPhotonMs 为 null，不能生成完整手感 PASS |
| 自然地图低反差发白 | 成功识别 $\Delta Y < 8$，标为 low_contrast_washed_out，不返回 not_determined |
| 强制有限范围对照组 | software_yuv_limited 成功映射 $(Y-16)\times 255/219$，恢复道路高反差 |

### 16.2 安排实车前的出门门槛

必须先交付一份实际可打开的示例归档，并逐项展示：

- 参考、raw、RGB、帧身份与指标分别来自哪里。
- 哪些字段是真实采到、哪些 unavailable，不能用假值补齐。
- 已知错误夹具能触发正确结论，缺数据时不会说正常。
- 一组失败或被中断后，前面结果仍可打开并重新发布。
- App 显示大小／哈希与电脑收到的文件一致。
- UI 完整展示请求与实际模式及回退。
- 普通／R8 包分别验证关键采样和发布入口保留；不能只检查类名存在。

这里的软件示例不能证明车机驱动颜色已修好；它证明工具具备可验证的采集和交付能力。
没有这些前置证据，不应再次让用户反复上车做全组合测试。

### 16.3 实车验收

停车、已配对、同一手机和可比画面下进行一轮：

- 用户只选一次 HEVC，启动后无需手动修改多套设置。
- 每次进入模式有明确操作提示和实际模式核验。
- 用户结束后已完成组先落盘，再自动断连、静默缓冲、释放、切换和重连。
- 每组都有颜色可判定程度、道路边缘反差评分、客观局部性能与用户手感记录。
- 任一组失败不影响已完成组，恢复和重发无需重跑采样。
- 颜色和跟手性是否最终达标，按实际证据判定，允许各组都未达标；
  不为了产出推荐结果强行挑一个“正常模式”。

## 18. 本规格审阅与落地结论

- 已固化包含 `software_yuv_limited`（发白闭环对照组）在内的引导测试模式。
- HEVC 为每轮单一选择，不隐式扩展测试组数。
- 针对自然地图场景制定 `roadEdgeContrastScore` 道路边缘阶梯差量化标准，消除“无测试卡即无法判断发白”的死锁。
- 规范纯内存 `RuntimeOverride` 会话事务模型，杜绝车机断电后临时配置残留污染日常使用。
- 明确 3~5 秒网络静默缓冲期，保护 Android 9 车载热点与 Wi-Fi 协议栈稳定性。
- 确立软件 YUV 管线低延迟规范：`eglSwapInterval(0)` 消除 VSync 阻塞，积压感知跳帧消除触控滞后。
- 已定义保存后切组、真实释放、设置恢复、失败与断点保留。
- 已定义“完成不等于通过”，缺失值不能填零、未知不能报正常。
